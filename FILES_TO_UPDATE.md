# Список измененных файлов для MySQL миграции

## Новые файлы (создать)

### База данных и конфигурация
- `database/schema.sql` - Схема MySQL базы данных
- `.env` - Файл с переменными окружения (создать на основе .env.example)
- `.env.example` - Пример конфигурации
- `SETUP.md` - Инструкции по настройке

### Библиотеки
- `lib/db.ts` - Подключение к MySQL
- `lib/auth.ts` - Функции аутентификации с JWT

### API роуты для аутентификации
- `app/api/auth/login/route.ts` - Вход в систему
- `app/api/auth/logout/route.ts` - Выход из системы
- `app/api/auth/me/route.ts` - Получение текущего пользователя

### API роуты для карточек (доступов)
- `app/api/cards/route.ts` - Список и создание карточек
- `app/api/cards/[id]/route.ts` - Получение, обновление и удаление карточки
- `app/api/cards/[id]/items/route.ts` - Список и создание элементов карточки
- `app/api/cards/[id]/items/[itemId]/route.ts` - Обновление и удаление элемента

### API роуты для задач
- `app/api/tasks/route.ts` - Список и создание задач
- `app/api/tasks/[id]/route.ts` - Получение, обновление и удаление задачи

### API роуты для пользователей
- `app/api/users/route.ts` - Список и создание пользователей
- `app/api/users/[id]/route.ts` - Получение, обновление и удаление пользователя

## Зависимости

Все необходимые зависимости уже есть в package.json:
- `mysql2` - MySQL клиент для Node.js
- `bcryptjs` - Хеширование паролей
- `jose` - JWT токены

## Порядок действий

1. Создайте все новые файлы из раздела "Новые файлы"
2. Замените файлы из раздела "Файлы для обновления"
3. Удалите `lib/storage.ts`
4. Настройте MySQL согласно инструкциям в SETUP.md
5. Создайте файл `.env` на основе `.env.example`
6. Импортируйте схему базы данных из `database/schema.sql`
7. Запустите приложение командой `npm run dev`

## Важные изменения

### Хранилище данных
- **Было**: localStorage (клиентское хранилище)
- **Стало**: MySQL база данных (серверное хранилище)

### Аутентификация
- **Было**: sessionStorage для токенов
- **Стало**: HTTP-only cookies с JWT токенами

### Безопасность
- Пароли теперь хешируются с bcrypt
- JWT токены с истечением срока действия
- Защита API роутов проверкой аутентификации
- SQL инъекции предотвращаются параметризованными запросами

### API структура
Все операции CRUD теперь выполняются через REST API:
- `GET /api/cards` - получить все доступы
- `POST /api/cards` - создать доступ
- `PUT /api/cards/[id]` - обновить доступ
- `DELETE /api/cards/[id]` - удалить доступ

Аналогично для tasks и users.
